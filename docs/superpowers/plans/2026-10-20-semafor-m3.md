# Semafor M3 Implementation Plan — probes, baselines, verdicts, divergence

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Semafor actively measures how the subscription frontier models *feel* — streaming latency probes for Claude and GPT‑6 Astra, learned baselines, a pure verdict ladder (OK/BUSY/DEGRADED/CRAWLING/LIMITED/UNKNOWN), and a status-page divergence banner — per spec §7–§8.4 and the M3 row of §13.

**Architecture:** Extends the existing SwiftPM package: providers gain real `probe()`/`statusPage()` implementations; a new `ProbeScheduler` actor owns adaptive cadence (activity-aware, quiet hours, daily cap); probes land in the JSONL `SampleStore` next to limits; pure `BaselineEngine` + `VerdictEngine` compute per-provider verdicts the AppModel renders into the popover. Zero new dependencies; the Codex probe streams directly from the ChatGPT backend, the Claude probe drives the `claude` CLI as a subprocess.

**Tech Stack:** Swift 6.4 toolchain, swift-tools-version 6.2, Swift 6 mode, macOS 14+, Foundation `URLSession` (`URLSessionDataDelegate` for SSE — `bytes(for:)` is macOS 15+), Foundation `Process` for the CLI probe, Network.framework `NWListener` for the test-only stub SSE server, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-10-20-semafor-design.md` (§5–§8.4, §9, §11–§13)

Codex `.fast` body uses `"service_tier": "priority"` — not spike-verified; acceptable because the toggle ships off by default and a rejected param surfaces as `.streamFailure`, not a hang.

## Global Constraints

- swift-tools-version 6.2, `swiftLanguageModes: [.v6]`, `.macOS(.v14)`; zero third-party dependencies (Foundation, SwiftUI, Security, Network-for-tests only).
- Credentials never logged, stored, or included in error strings; everything user-visible passes through `redact()`. The sample store holds only probe/limit/control/status records.
- Probes obey spec §7: serial, one attempt (zero retries), 20 s hard timeout per probe, ±20 % deterministic jitter, daily cap (default 600, includes control requests), "Test now" bypasses cadence/quiet-hours/cap.
- Verdict rules are a pure function — every input explicit, no hidden state (spec §8.2). Priorities: `UNKNOWN > LIMITED > CRAWLING > DEGRADED > BUSY > OK`.
- Every task ends with `swift test` green and its own commit. Beacon-style imperative commit messages.
- Tests use Swift Testing (`@Test`, `#expect`).

## Review Focus

Failure modes the spec implies that happy-path tests miss; each gets its pinning test in the task named:

- **Hung/torn SSE stream** — stub server accepts, sends nothing, or dies before `response.completed` → probe ends at timeout with `.timeout`/`.streamFailure`, `tokensPerSecond: nil`; no hang, no zombie task (Task 3).
- **Claude CLI unavailable or noisy** — binary absent, nonzero exit, non-JSON lines interleaved → mapped outcomes (`probeUnavailable`, `.streamFailure`), parser skips garbage without crashing (Task 4).
- **VPN flake misdiagnosis** — control probe bad ⇒ verdicts go `UNKNOWN(network)`, DEGRADED/CRAWLING alerts and the divergence banner are suppressed — the spec §13 acceptance for "control probe suppresses false alarms" (Tasks 5, 9).
- **Baseline poisoning / flapping** — one 100 s outlier among fast probes must not fire DEGRADED (median/MAD + floor + N-consecutive rule); baseline switches learned↔default exactly at 20 samples (Task 8).
- **Store forward/backward compatibility** — new `probes`/`controls`/`status` JSONL lines decode on new builds; unknown-type or torn lines are counted corrupt and skipped, never thrown (Task 1).
- **Clock anomalies** — probe samples with future timestamps excluded from baselines/runs; quiet hours spanning 22:00→07:00 (and inverted settings) evaluated correctly (Tasks 6, 7, 8).
